# 小手机 Tavo 插件设计

## 目标

在 Tavo 聊天页提供一个可拖拽的悬浮手机，包含角色管理、GitHub 内容导入和微信式社交空间。每个身份拥有独立手机数据；主聊天只接收微信摘要和剧情事件。

## 运行时架构

- `entry.js` 注册聊天、消息和生成生命周期钩子。
- `/chat/body/end` 挂载自包含 `ui/phone.html`；入口按钮可拖拽并避开 Tavo 导航栏和输入区。
- 源码使用原生 JavaScript/CSS 按模块组织，由 esbuild 生成最终 fragment。
- 角色卡、预设、世界书和 Persona 使用 Tavo 原生资源 API。
- Tavo 1.3.3 插件侧没有 `tavo.chat.create/get`，所以微信和角色间会话保存于插件全局状态；一次性生成显式传入上下文，不写入主聊天。

## 数据边界

- 全局状态：身份、联系人映射、插件会话、朋友圈、GitHub 配置和候选角色。
- Chat scope：当前主聊天的回合数、分析游标和微信摘要。
- 身份切换会整体替换联系人、会话、朋友圈和主动消息设置；Tavo 资源库仍可复用。
- 角色身份首次使用时创建 shadow Persona，以便作为微信中的发言身份。

## 三个 App

### 角色管理

按“用户消息 + 角色回复”统计完整回合。达到配置阈值后分析最近剧情，按已知角色和候选去重；候选必须经过编辑和确认才写入角色库。

### 内容导入

配置 owner/repo/branch/path/token，调用 GitHub REST API 浏览文件。支持 Tavo/CCv3、CCv2、SillyTavern World Info 和 PNG 角色卡；导入提供新建、覆盖、跳过策略。

### 微信

包含微信、通讯录、发现、我的四个 Tab。微信会话和角色间会话由插件保存；朋友圈支持角色动态和当前身份发帖；“我的”切换完整手机身份。

## 联动规则

- `generation:prepare` 注入最多 3 个相关微信摘要。
- `generation:success` 异步触发新角色检测、剧情事件判断和社交后台任务。
- 主动消息优先由剧情事件触发；同场角色不发消息；长期未联系角色按概率和冷却策略处理。
- 角色间后台聊天受身份开关控制，只生成有限消息并保留未读状态。
- 任何网络、JSON、Tavo runtime 或模型失败都进入可重试状态，不阻塞主聊天。

## 默认值

- 角色检测：开启；每 5 个完整回合；分析最近 5 回合。
- 主动聊天：全局和联系人默认关闭；冷却 30 分钟；长期未联系 24 小时；概率 20%。
- 角色间后台聊天：默认关闭。
- 微信摘要：每个会话最多 600 字，主聊天最多注入 3 个摘要。
